# Agent instructions: infra/

OpenTofu: `bootstrap/` (one-off: state, keys, identities, GitHub environments; [README](bootstrap/README.md)) and `app/` (the site's resources, one state per environment). The rules in the root [AGENTS.md](../AGENTS.md) apply; these add to them.

- **Never** `tofu apply`, `just bootstrap-apply` or `just bootstrap-migrate`, and no Azure sign-in of your own. `tofu plan` only when the maintainer asks, and never post a plan: resource addresses and change counts only (`scripts/plan-summary.sh`).
- Check with `just infra`, as its own call outside the Claude sandbox: `tofu validate`, TFLint and Checkov start plugins over Unix sockets, which the sandbox refuses. A sandboxed `tofu init` needs `TF_PLUGIN_CACHE_DIR` set to a directory under `~/.cache`.
- An exception to a check is inline, with a reason: `#checkov:skip=<check>:<reason>` in the resource, `# policy:waive <rule> <reason>` above it ([policy/README.md](../policy/README.md)). A new Rego rule comes with `conftest verify` tests (`just policy-test`, `just policy-check`).
- Deployment values are GitHub environment variables (`TF_VAR_*`) and secrets, never defaults in the code; app secrets go in the environment's Key Vault.
- Provider pins are patch ranges (`~> 5.12.0`); Dependabot proposes the rest. azurerm's quirks so far: the `hidden-link` tag (F-0057), a gone storage account failing the refresh (F-0020), providers not registered by default (the bootstrap registers them): [engineering notes](../docs/engineering-notes.md#opentofu).
- `infra-apply` compares a push with the last successfully applied commit (`scripts/last-applied.sh`), so a change that waited behind a cancelled run is still applied.
- Design guidance, not enforced in CI: the Cloud Adoption Framework's [naming](https://learn.microsoft.com/azure/cloud-adoption-framework/ready/azure-best-practices/resource-naming), [abbreviations](https://learn.microsoft.com/azure/cloud-adoption-framework/ready/azure-best-practices/resource-abbreviations) and [tagging](https://learn.microsoft.com/azure/cloud-adoption-framework/ready/azure-best-practices/resource-tagging); the [Microsoft cloud security benchmark](https://learn.microsoft.com/security/benchmark/azure/overview) and the [Container Apps baseline](https://learn.microsoft.com/security/benchmark/azure/baselines/azure-container-apps-security-baseline); the [OpenTofu style conventions](https://opentofu.org/docs/language/syntax/style/); the [Azure Verified Modules specifications](https://azure.github.io/Azure-Verified-Modules/specs/module-specs/).
