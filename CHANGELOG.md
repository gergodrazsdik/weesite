# Changelog

All notable changes to Weesite are in this file, from release 1.0 on. What came before is in the [tracker archive](docs/history/tracker-1.0.md) and the git history.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **An SEO title for posts and pages** (`seo_title` in the front matter, "SEO title" in the editor): a shorter title for the browser tab and search results, for an item whose title is too long there. The page's heading, link previews and feeds keep the title. The editor counts the whole tab title, the site's name included, against the 70 characters search engines show, and the editor tools' `preview_item` warns when it's longer.
- **`set_tags` for apps** (the editor MCP endpoint): adds tags to a post or page and removes others, without the app sending the whole file again, so nothing else in it can change by mistake. It answers with the tags now and the ones no other item carries, to catch a misspelt tag.
- **`edit_item` for apps** (the editor MCP endpoint): changes part of a post or page by replacing exact text, front matter included, so an app needn't send the whole file back for a small change. Each edit's text must appear exactly once, and the edits apply all or none; when someone saved the item meanwhile, they're applied to the new version if their text is still there. It answers with the lines that changed, and otherwise works as `update_item`: the status stays, and apps allowed drafts only change drafts only.
- **Ask before publishing, in the app**: an option on the consent page for apps allowed to publish. With it, `set_status` asks you in the app ("Publish 'Title' now?") before it publishes or schedules an item, and changes nothing when you decline. It needs a client that supports MCP elicitation; one that doesn't is refused and told to publish in `/admin`. Answers are in the audit log. It's a convenience: the consent's levels remain what limits an app.
- **An editing skill for apps** (the editor MCP endpoint, experimental): apps that load skills from MCP servers, such as Claude and Claude Code, get `weesite-editor`, which teaches the editing workflow behind the tools: versions and conflicts, drafts and publishing, alt text, tags and previews. The public endpoint serves no skills ([mcp.md](docs/mcp.md#the-editing-skill-experimental)).
- **File uploads for apps** (the editor MCP endpoint, experimental): `add_media_file` adds an image or file to Media through the draft MCP file uploads extension, for clients that support it: the client sends the bytes itself, inline or to a one-time target, so they pass through neither the model nor a shell. Files are checked and stored only once the client confirms, as every upload is; until then they wait in a new private Blob container, `uploads`, so any replica can finish an upload. `create_media_upload` and `upload_media` stay for other apps ([mcp.md](docs/mcp.md#file-uploads-experimental)).
- **Preview links for apps** (the editor MCP endpoint): `create_preview_link` gives a link to a saved draft's preview page that an app can open in its own browser, or fetch, without signing in, so an agent can look at a post as visitors will before it's published. A link shows the last saved version for an hour, ends when the app is disconnected, and is in the audit log.
- **Diffs are highlighted** (` ```diff ` or ` ```patch `): added lines in green, removed ones in red, changed ones in amber, with the hunk ranges and file headers marked. The `+`, `-` and `!` that start the lines still say which is which without colour. Diffs were plain text before.

### Changed

- **Code is highlighted by a native library** (syntect, with bat's syntaxes; ADR 0012) instead of TextMateSharp: a new replica's first render takes milliseconds rather than seconds, and the app uses about 125 MB less memory. Highlighted code looks slightly different where the grammars split tokens differently, and the editor's Code block dialog lists about 190 languages instead of 71; every fence name that worked before still picks its language. Ten languages bat's set lacks, or has an older grammar of (Bicep, Handlebars, HLSL, Just, Perl 6, Pug, Razor, Rego, ShaderLab and Visual Basic), keep the grammars Weesite had, converted; [grammars.md](docs/grammars.md) lists every language and its fence names.
- **Building from source needs Rust** for that library (`native/highlight`): rustup's stable toolchain, at least the `rust-version` its `Cargo.toml` names, plus a C compiler ([dev-setup](docs/dev-setup.md)). The container image builds it in a stage of its own, so deploying from the published image needs nothing new.
- **A new replica is ready about 3 seconds sooner on Azure.** The Key Vault secrets (the sign-in clients, the admins, the SMTP settings) load in the background instead of before the app starts: public pages don't wait for them, and sign-in, the admin, the editor MCP endpoint and mail wait the few seconds they take. If they still aren't in after 30 seconds, those answer 503 and the log says why. A wrong SMTP setting no longer stops the app from starting: inviting an editor and the digests say what's wrong instead.
- **A new replica is ready sooner.** It no longer waits for the search model: the first search index is built on keywords, and search by meaning follows a few seconds later, once the model has loaded. On Azure the model and the code highlighter start loading while the app waits for Key Vault, and the startup log says how long the managed identity's first tokens took.
- **The invisible proof of work costs bots about 25 times more** for the same wait: the browser now derives PBKDF2-SHA-256 keys (5,000 iterations) instead of single SHA-256 hashes, which native code solved over 30 times faster than a browser. A visitor still waits about half a second. `Visitor:ProofMaxNumber` now counts keys, and its default goes from 100,000 to 1,000: if you set it, lower it about a hundredfold. A page opened before the upgrade sends comments and reactions again once it's reloaded; until then its contact messages arrive marked unverified.
- **Running Weesite locally needs the Aspire CLI 17** (`just aspire`, `just uat`): the AppHost moved to Aspire 17, whose C# AppHosts build and run with the dashboard and orchestrator from the CLI. Update the CLI with `aspire update --self` (or `dotnet tool update -g Aspire.Cli --version 17.0.0` for the .NET tool). Without a CLI, the AppHost's build fetches the matching one from NuGet. The app's Azure Storage clients use Aspire 17's integrations, with the same settings; deploying is unchanged.

### Fixed

- **The re-index job's and the seed command's logs reach Application Insights**, and so do the app's first lines at startup (the search model's load, the Key Vault secrets, a missing `Site:BaseUrl`). The Azure Monitor exporter takes logs only once a host has started; the commands never started theirs, and the app wrote those lines before. They were in the container's console log only.
- **Feeds and attachments stay out of search results.** The feeds and the media files that download (attachments such as text or PDF files, and SVG images) say `X-Robots-Tag: noindex`. Search engines still read the feeds and follow their links, but an attachment no longer shows up as a result of its own, and Search Console lists these addresses as excluded on purpose instead of "crawled, not indexed". Photos and other images stay in image search.
- **The clean-up of app registrations** works with Table Storage. It listed every registration without its ID and stopped there, so registrations never granted, or unused for a month, were never deleted. Expired codes, upload addresses and grants were cleaned up as before.
- **Aligned table columns** (`| :---: |` or `| ---: |` in Markdown) are aligned. The alignment was written as an inline style, which the site's Content Security Policy blocks, so the column stayed left-aligned and every cell logged a policy error in the browser's console, which Google Search Console reports.
- **A page's "On this page"** is laid out as a post's: beside the text on wide screens, a list to open at the top on medium ones, and a plain list at the top on phones. It used to sit in the text column under the title at every width.
- **The marks on notices** (the tick on "Saved.", the warning sign on errors) are drawn as icons, so they no longer lose their top on systems whose fallback font draws them taller than the line.
- **The sample privacy policy and terms** match what 1.1 does: they list the contact form's security cookie, say that a reaction can be taken back only on its day, what the comment and message notices contain and who gets them, and what happens to comments left waiting, deleted or removed, and the terms add rules for comments. If you copied the 1.1 samples, compare yours with them (`seed/content/pages/privacy.md`, `terms.md`).

### Security

- **No telemetry to Microsoft from the search model.** ONNX Runtime, which runs the embedding model, sends usage data to Microsoft by default in its official builds, on Linux too: each time the app or the re-index job started, it uploaded an event with a device ID, the operating system, the CPU, the memory and the process name, and where it could, kept the device ID and a queue of events in `~/.cache/Microsoft/DeveloperTools/.onnxruntime/`. The app now turns this off before it loads the model, and the image sets `ORT_DISABLE_TELEMETRY=1`. No visitor data was in these events. Nothing to do on an upgrade; on a machine where you ran Weesite before, you can delete that folder.

## [1.1.0] - 2026-11-24

### Upgrading from 1.0

Take the release as [Keeping a fork up to date](docs/deploy.md#keeping-a-fork-up-to-date) describes, then:

1. **Run the bootstrap around the release.** 1.1 changes it: pull request plans wait in a new `plan` environment, the helper workflows get identities of their own, the plan identities read fewer Key Vault secrets, the web app sends telemetry with its own identity, and the app gets the role that lets it delete old versions. Follow [Updating an install from 1.0](docs/deploy.md#updating-an-install-from-10): set `plan_secrets_group_scope = true` and run `just bootstrap-plan` and `just bootstrap-apply`; take the release onto `main`, and promote the new image to prod before you approve `infra-apply`'s prod step; then remove `plan_secrets_group_scope` and run the bootstrap again. Until the first bootstrap apply, pull request plans can't sign in.
2. **Load the country database.** Once `infra-apply` has run, start the `geoip` workflow from the Actions tab; otherwise page views record no country until its monthly run ([Visitor countries](docs/deploy.md#visitor-countries-geoip)).
3. **Move the special pages.** Site settings no longer find the home page's page, the privacy policy, the terms or the contact text by slug, so the footer links disappear until you move them: open each under Pages, tick **No address of its own** and save, then choose it again in Site settings ([Privacy policy and terms](docs/deploy.md#privacy-policy-and-terms)).
4. **Update your privacy policy.** Visitors' countries are recorded by default: say so, or turn off **Record visitors' countries** in Site settings. Before turning on comments, reactions or the contact form, add their sections too. The sample [privacy policy](seed/content/pages/privacy.md) has wording for each.
5. **Set the address of each environment without a custom domain,** such as test: add `"Site__BaseUrl"` with its Container Apps address (`just url <env>`) to its app settings (`APP_SETTINGS_TEST` for test) and start `infra-apply`. Without it the comment and message digests leave out their link to the admin, and the app warns at startup ([App settings](docs/deploy.md#app-settings)).
6. **Require the new checks:** run `just github-settings <owner>/<repo>`; pull requests now also need `format`, `browser (minified)` and `image` ([Install, step 9](docs/install.md#9-turn-on-the-required-checks)).
7. **With a CDN or another proxy in front of the ingress,** set `ForwardedHeaders:Proxies` to 2, so the rate limits count each visitor rather than the proxy ([Proxies in front of the app](docs/deploy.md#proxies-in-front-of-the-app)).
8. **Tell the people who use apps:** the public MCP tool `list_content` now answers in pages, and an app whose return address uses a custom scheme must register again unless the scheme is a reverse domain name (see Changed and Security).

### Added

- **Comments on posts** (off by default): visitors whose browsers run JavaScript write a name and up to 1,000 characters of plain text; addresses become `ugc` links, lines starting with `>` or `|` become quotes, and Reply quotes a comment. Nobody signs in: the writer's browser keeps a key to edit or delete their comment. Every comment and edit waits under the admin's new **Comments** page, or on the post itself, until an editor approves it (admins every post's, authors their own); admins can remove a published comment. Signed-in editors comment under their own name, marked. Comments that wait 30 days without a decision are deleted, moderators get an hourly digest by email, and a post can close its own comments ([Comments](docs/deploy.md#comments)).
- **Reactions to posts** (off by default): a React button gives a post one reaction (Like, Love, Thanks, Insightful or Funny), which the visitor can change or remove; the counts of each open from the post. No sign-in and no cookie: the server counts at most one per post per day from an address and browser, through a hash that changes daily ([ADR 0011](docs/adr/0011-visitor-input.md)).
- **A contact form** (off by default): `/contact` takes a name, an email address and up to 1,000 characters of plain text, under a page you choose, and the menu can link to it. Messages wait under the admin's new **Messages** page until you delete them, at most 12 months, and an hourly digest mails new ones to a private "Messages go to" address. It works without JavaScript; such messages arrive marked unverified ([Contact form](docs/deploy.md#contact-form)).
- **Spam protection without third parties** for comments, reactions and messages: a hidden field, a minimum time, an invisible proof of work in the browser, plain-text rules, hourly limits per address (5 comments or messages, 20 comment edits) and a 32 KB request limit. IP addresses are never stored, only a hash that changes daily.
- **A time zone and a clock:** Site settings choose the site's time zone (UTC by default) and a 24- or 12-hour clock, used in the admin, the digests, the analytics days and scheduling. Times are still stored in UTC, and apps and feeds get UTC.
- **The editor says when the item was saved elsewhere** while you have it open (another tab, another editor, an app), and links to the saved version.
- **Media:** JSON, YAML and TOML files upload like other files (JSON and YAML must parse), and an image's description can be edited in Media without uploading the file again; the media picker fills it in when you choose the image.
- **Tags:** Tags → Suggest colours groups the tags by what their posts are about and suggests a colour for each group, applied only to the ones you tick. A tag's description is now its page's meta description, for search engines and link previews.
- **Menu items have a Remove button.**
- **Visitors' countries in the analytics** (on by default): a person's page view records the country of their IP address, looked up in memory in DB-IP's IP to Country Lite (CC BY 4.0); the address isn't stored. The new `geoip` workflow refreshes the database monthly ([Visitor countries](docs/deploy.md#visitor-countries-geoip)).
- **More analytics:** the page refreshes every 30 seconds (it can be paused), its lists are tabs and the per-day table opens in a dialog; reactions show by day, kind and post. Analytics → **Posts report** (admins only) lists every post with its page views, visitors, AI agent and bot views, comments and reactions over 7, 30 or 90 days, sortable and as a CSV download.
- **IndexNow** (off by default): turned on in Site settings, the site tells Bing and the other engines that take part about a post or page as soon as it's published, changed or taken down ([Search engines](docs/deploy.md#search-engines)).
- **For apps on the editor MCP endpoint:** `create_media_upload` gives an app a one-time address to upload, or replace, a file of up to 20 MB with curl, rather than sending it through the model as base64 ([Upload larger files](docs/mcp.md#upload-larger-files)); apps that run commands in a sandbox, such as Claude, need the site's domain allowed there. `list_tags` lists the tags in use, so apps reuse them. `list_comments`, `moderate_comment` and `delete_comment` moderate comments, for apps allowed to publish ([Ask before publishing](docs/mcp.md#ask-before-publishing)).
- **For running a fork:** a weekly `tool-updates` workflow lists the pinned tool versions due an update, and keeps one issue about them when the repository variable `TOOL_UPDATES_ISSUE` is `true`. `just uat <pr>` runs a pull request locally before it's merged; it refuses a fork's pull request unless given `--fork` ([Trying a pull request locally](docs/dev-setup.md#trying-a-pull-request-locally)).

### Changed

- **Special pages:** the home page's page, the privacy policy, the terms and the contact form's text are pages without a slug (**No address of its own**), which Site settings choose and show at `/`, `/privacy`, `/terms` and `/contact`. They aren't in the menu; search, the sitemap, `llms.txt` and the MCP tools have them, with Markdown at `/privacy.md`, `/terms.md`, `/contact.md` and `/index.md`. `privacy`, `terms`, `contact` and `visitor` are reserved slugs. See Upgrading.
- **The public MCP tool `list_content` answers in pages:** `items`, `total` and `nextOffset`, taking an `offset`, rather than a list that stopped at 50 without saying so. Apps that read the answer as a list need the `items` field. An unknown `kind` is refused.
- **The reset has its own page** (Site settings → danger zone), where you tick what to delete: content, media, settings and the search index at first, and comments, reactions, messages, analytics, added editors, connected apps, the audit log, the spam counters and uploaded backups when ticked. You're signed out only if the reset deleted you.
- **The admin, more consistent:** on a phone the sidebar is a slim bar with a **Menu** button; a page's explanation is under an (i) beside its title; notices, fields and confirmations look the same on every page, and after a save the focus goes to the notice. Actions that ask first share one dialog, with the safe choice first; only deleting a post, a page or a media file, and the reset, ask you to type its name, with a Copy button beside the field. The sidebar shows waiting comments and unread messages as badges.
- **Admin lists:** Posts and Pages sort by their columns; Posts, Media and the audit log have a **Filter** button; the audit log reads in words, with editors' names and items' titles (the CSV keeps the codes); Media's count leaves out archived files; the menu editor shows where each item goes; Editors shows where each connected app comes from and when it was last used; Backup names what it leaves out.
- **The editor:** the top bar keeps Save in one place and says when there are unsaved changes; in the split view the text and preview scroll in step; discarding text kept in the browser asks first; and it says that scheduling a post doesn't change its Date.
- **The analytics page shows at once** and fills in its report when it's read; finished days are kept in memory for a few minutes, so a refresh reads only yesterday and today.
- **The public site:** messages, links and post counts look the same everywhere; every page with two or more sections lists them under "On this page"; small links are at least 24 px tall; each code block's Copy button is named after its block and footnote links have names for screen readers; the home page's years link to their part of the blog.
- **Search speaks plainly:** it says what it finds, counts the results, and when the Posts or Pages filter rules out every match, says how many of the other kind match.
- **Infrastructure checks:** the policy baseline is stricter about Microsoft Graph permissions, wildcard role actions and tags ([policy](policy/README.md)); `just merge` waits for every check on a pull request; the `dco` check also wants a Conventional Commits header on every commit.

### Fixed

- **Scheduled posts and pages are saved as published** when their time comes, with an audit entry, rather than staying "scheduled" in storage.
- **Earlier versions of long-unchanged posts are kept:** storage deleted a version 90 days after its text was written, so editing an old post lost its earlier text within a day. Each post, page and settings file now keeps its newest 50 earlier versions, and older ones until 90 days after they were replaced (`Content:VersionsKept`, `Content:VersionDays`); this needs the bootstrap apply in Upgrading ([Backups and restore](docs/deploy.md#backups-and-restore)).
- **The site keeps running through storage and search failures:** a storage timeout in background work or at startup no longer stops the app, and a search index that can't be built leaves the previous one, or keyword search, in place.
- **Content loads reliably:** a replica that starts during a save loads it; pages keep one order across replicas; a published post wins over a draft with the same slug; a `null` in `site.json` or `authors.json` no longer stops every load; text nested too deeply shows as plain text rather than failing saves, previews and the index.
- **Caching:** related posts no longer come from the previous index after an edit; an address spelt with capitals is no longer cached for every spelling; redirects from earlier slugs are kept for a day rather than for good.
- **Feeds and files:** a control character in a post no longer breaks the Atom feeds; a tag's feed answers 404 rather than 500 when its last post goes; media, feeds, the sitemap, `robots.txt`, `llms.txt`, Markdown versions and social cards answer HEAD; media in Azure answers range requests and sends its length; a social card for a title made only of emoji no longer fails; an uploaded WebP named like a resized copy, such as `hero-1920w.webp`, is kept (as `hero-1920-w.webp`).
- **Uploaded photos are kept as they are when possible:** a JPEG or WebP without metadata is stored as uploaded unless re-encoding makes it smaller, rather than always re-encoded at quality 85.
- **The public site:** without JavaScript, the theme switch on an error page returns to the address asked for; signing in from `/admin/sign-in/` works; the home page's heading levels are right; the 404 and 410 pages' tab titles end with the site's name; Hungarian breadcrumbs say "címkék", and short dates have no leading zero.
- **Forms are sent once:** a second press while the first was on its way sent the form again, so a slow action such as the reset could run twice.
- **Saving without changes** adds no version or audit entry, in the editor, on the settings pages and through `update_item` (which answers `unchanged`); a file's formatting is kept until something in it changes.
- **The editor:** Ctrl+S saves before a field has the focus, and not behind the media picker; the reading time counts the plain text, as the site does; an empty Language stays empty rather than becoming the site's language, also over MCP; inserted images go where the cursor was, as a paragraph of their own; restoring kept text over a newer version shows the conflict; the export's footnote note gives the real numbers; the media picker shows whole file names.
- **Edits that went missing:** a profile save no longer overwrites a damaged `authors.json`; links beyond the form's rows are no longer dropped; the logo, favicon, banner and home page photo count as uses of their media files, and replacing one updates Site settings.
- **Actions that stop partway say so:** a reset or import that fails partway says what it did and writes its audit entry; deletes, uploads, replacements and re-index requests finish their audit entry and clean-up even when the browser tab closes; an invitation that went out says so.
- **The admin:** the menu marks the right section, also on sub-pages; tables fit a phone without the page scrolling sideways; the admin and its sign-in say `lang="en"` on a site in another language; without JavaScript, actions that should ask first no longer act unasked; admin pages are quicker with many media files.
- **App access ends cleanly after 90 days,** telling the app to ask again and writing `oauth-grant-ended` to the audit log.
- **Deploys and infrastructure:** a deploy waits until the new revision itself is healthy, so a broken image fails the deploy; the re-index job runs only when asked; app setting names compare in any case, as the app reads them; the image builds on arm64 under emulation; a recipe or lint change no longer asks for prod approval of an empty plan; pushes to GHCR are retried; Dependabot's OpenTofu pull requests no longer fail `infra-plan`.
- **Visitors no longer fill the audit workspace's daily cap,** which stopped the Key Vault and content audit for the rest of the day; an alert emails the subscription's Owners if it's reached. Old page views are deleted even with counting off.

### Security

- **Pull request plans wait for approval** in the new `plan` environment, the only place a pull request can sign in as the plan identity; pull requests that change no infrastructure still pass without waiting.
- **Narrower CI identities:** the plan identities read only the Key Vault secrets OpenTofu writes; `seed`, `load-test` and `geoip` run in new `test-ops` and `prod-ops` environments as ops identities with only the roles they need, and `geoip`'s prod upload waits for approval; admins can no longer bypass test's rules.
- **Application Insights takes telemetry only through Entra ID;** the connection string alone no longer sends anything.
- **Only reviewed plans, images and commits ship:** `infra-apply` applies only the reviewed plan; `promote` deploys only this repository's own image; OpenTofu is checked against a pinned SHA-256; `just merge` wants each commit signed by a key in `WEESITE_MERGE_SIGNERS` (by default your own signing key).
- **Rate limits count fairly:** per-minute limits count an IPv6 client by its /64 network and match a path whatever its case, and `ForwardedHeaders:Proxies`, `KnownProxies` and `KnownNetworks` set which forwarded addresses count ([Proxies in front of the app](docs/deploy.md#proxies-in-front-of-the-app)).
- **Limits on work per request:** each text is rendered once and reused; the live preview, exports and `preview_item` take one turn per editor, answering 429 after a short wait; a post or page has at most 20 tags (items with more keep them until edited); the public `/mcp` refuses bodies over 256 KB and `/oauth` over 64 KB.
- **Only the image formats the site uses are decoded:** JPEG, PNG and WebP, and SVG only for a logo's or favicon's icons. AVIF logos, which only an import could bring, are no longer drawn: choose another.
- **The admin is harder to misuse:** it refuses embedded requests such as images, so a post can't make an editor's browser call an admin address; authors see only what they may edit; pages show only their own notices; importing settings from a backup asks first; the reset ends removed editors' sign-ins and revokes their apps, and only an admin from `Site:Admins` can delete the audit log; tag colours are saved only for tags in use.
- **Apps and sign-in:** no app may replace the files Site settings use (logo, favicon, banner, home page photo); sign-in errors stay on the site; an app's custom return scheme must be a reverse domain name, such as `com.example.app:` (RFC 8252); a sign-in code exchanged twice at once leaves no access.

## [1.0.0] - 2026-11-16

The first release: a personal site on Azure that you deploy from your own fork, with an editor, search and agent support. [Install Weesite](docs/install.md) walks through a first install.

### Added

- **The public site:** posts and pages from Markdown, tags with colours, related posts, a one-level menu and a home page you set up. Reading aids: "On this page", heading links, a top link, images that open larger, code highlighted on the server with an optional file name, footnotes and print styles. Light, dark and system themes, with your own colours. It works without JavaScript.
- **Search:** keyword and meaning search in the app itself (SQLite FTS5 and a local embedding model, merged by rank), English by default and about a hundred languages with the multilingual model. No outside search service.
- **Search engines and feeds:** canonical addresses, structured data, social cards drawn for every post, a sitemap, `robots.txt`, Atom and JSON Feed.
- **Agent support:** `llms.txt`, every page as Markdown (`Accept: text/markdown`), a read-only MCP endpoint for the public content, and an MCP endpoint for editors (`/mcp/editor`) with OAuth sign-in, three consent levels, Client ID Metadata Documents and dynamic registration.
- **The editor at `/admin`:** sign-in with Microsoft or Google; admins and authors; a Markdown editor with a toolbar, live preview and autosave; drafts, scheduling, archiving and deleting; versions with a diff and restore; media with alt text, WebP sizes and references; the menu, theme, tags, site and footer settings; editors with email invitations; an audit log with a CSV export; backups to download and import; a factory reset; and HTML export of a post for publishing elsewhere.
- **Analytics:** page views counted on the server, without cookies and without storing IP addresses, AI agents included; an editor's own visits are left out.
- **Languages:** one site language, any language; the public text in English and Hungarian; posts in another language marked as such.
- **Infrastructure:** OpenTofu for Azure Container Apps, Blob and Table Storage, Key Vault and monitoring, test and prod, with a bootstrap that sets up the state, its encryption, the identities and the GitHub environments. A second install fits in the same subscription.
- **Delivery:** GitHub Actions that lint, test (unit, integration and browser), scan and publish the image, plan and apply the infrastructure with a policy baseline (Rego, TFLint, Checkov), deploy to test, and promote the same image to prod after approval.
- **Security and accessibility:** a strict CSP with no inline code, `__Host-` session cookies with a seven-day limit, rate limits, upload and import checks, audit logs for Key Vault, storage and the state, and WCAG 2.2 AA checked with axe in the browser tests and by hand with a screen reader.
