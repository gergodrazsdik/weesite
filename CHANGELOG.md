# Changelog

All notable changes to Weesite are in this file, from release 1.0 on. What came before is in the [tracker archive](docs/history/tracker-1.0.md) and the git history.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **A contact form:** turned on in Site settings, `/contact` takes a name, an email address and a plain-text message of up to 1,000 characters, under a page you may choose; the menu can link to it as **Contact form**. Messages wait under the admin's new **Messages** page until you delete them (at most 12 months), and an hourly digest mails new ones to a private "Messages go to" address. Spam is held back without third parties or puzzles: a hidden field, a minimum time, an invisible proof of work in the browser, plain-text rules and 5 messages an hour per address; IP addresses are never stored. The form works without JavaScript; such messages are marked unverified ([deploy](docs/deploy.md#contact-form)). A page that already has the slug `contact` keeps working: choose it as the page above the form.
- **Comments on posts:** turned on in Site settings, posts take comments from visitors whose browsers run JavaScript: a name and up to 1,000 characters of plain text, with addresses as `ugc` links and lines starting with `>` or `|` as quotes, nested as in mail; Reply quotes a comment into the form, with who wrote it and when. Ten show at a time, oldest first, each with a coloured bar for the post's author, editors, the visitor's own and those waiting (four new colours in the colour theme), and dates such as "2 days ago" in the site's language. A comment whose text changed after it was published says "edited", and one its writer deletes, or a moderator removes once published, leaves a marker in its place where replies follow it, so the conversation still reads. Signed-in editors comment under their own name, marked, and moderators approve and reject on the post itself; admins can also reject a published comment there. Every comment and every edit waits under the admin's new **Comments** page until an editor approves it (admins every post's, authors their own), and moderators get an hourly digest. No sign-in: the writer's browser keeps a key to edit or delete their comment, and the site keeps only its hash. Spam is held back as on the contact form, with the proof of work required. A post can close its own comments. The editor MCP endpoint gets `list_comments`, `moderate_comment` and `delete_comment` ([deploy](docs/deploy.md#comments), [MCP](docs/mcp.md)). Off by default.
- **Reactions to posts:** turned on in Site settings, a visitor whose browser runs JavaScript gives a post one reaction (Like, Love, Thanks, Insightful or Funny) from a React button, and can change or remove it. Under the post, React shows the visitor's reaction and the total, beside the comment count (which goes to the comment box) and Share; on the right, the reactions given open the count of each. No sign-in and no cookie: the browser remembers its reaction, and the server counts at most one per post per day from an address and browser, through a hash that changes daily, behind an invisible proof of work, with hourly limits per address and browser and per address alone. The analytics show reactions by day, by kind, and by post broken down by kind, with the post's comments beside them. Off by default ([ADR 0011](docs/adr/0011-visitor-input.md)); the sample privacy policy has a section on them.
- **A time zone and a clock for the site:** Site settings choose the time zone (UTC by default) and a 24-hour or 12-hour clock. The admin, the digest mails, the analytics days and the scheduled publish time use them; times are still stored in UTC, and what apps and feeds read stays UTC.
- **Larger uploads from apps:** the editor MCP endpoint's new `create_media_upload` tool gives an app a one-time address to upload a file of up to 20 MB with curl, so the file no longer passes through the model as base64 ([MCP](docs/mcp.md#upload-larger-files)). It can also replace a stored file, as `replace_media` does. Apps that run commands in a sandbox, such as Claude, need the site's domain allowed there.
- **Tags for apps:** the editor MCP endpoint's new `list_tags` tool lists the tags posts use, most used first, with their colours and descriptions, so an app reuses them instead of making up new ones ([MCP](docs/mcp.md)).
- **Changed elsewhere:** the post and page editor says when someone else saved the item while you have it open, in another tab, in the editor or through an app such as Claude. With unsaved changes, it says that saving will show the conflict, and links to the saved version.
- **Tag descriptions in search results:** a tag's description is now its page's meta description, so search engines and link previews show it instead of the site's tagline.
- **Suggested tag colours:** Tags has a Suggest colours page that groups the tags by what their posts are about and gives each group a colour, keeping colours already in use where it can; you can choose another colour for a group. Nothing changes until you tick the suggestions and apply them.
- **Visitors' countries in the analytics:** a person's page view records the country of their IP address, looked up in memory with DB-IP's IP to Country Lite (CC BY 4.0); the address is never stored. On by default; Site settings can turn it off.
- **The `geoip` workflow** downloads, checks and uploads the country database to each environment every month. It needs `infra-apply` for the new `geoip` container and its role ([deploy](docs/deploy.md#visitor-countries-geoip)).
- **A livelier analytics page:** it refreshes every 30 seconds without moving the page, and can be paused; the per-day table opens in a dialog, and the lists (pages, referring sites, bots and AI agents, countries) are tabs.
- **IndexNow:** turned on in Site settings, the site tells Bing and the other engines that take part about a post or page as soon as it's published, changed or taken down, rather than at their next crawl. Off by default ([deploy](docs/deploy.md#search-engines)).
- **JSON, YAML and TOML files in Media:** they upload like the other files and download from their links. A JSON or YAML file must parse; the refusal names the line that doesn't.
- **A posts report in the analytics:** Analytics → Posts report lists every post, published, scheduled, draft or archived, with its page views, visitors, AI agent and bot views, approved comments and reactions in the last 7, 30 or 90 days. Views of a post's earlier addresses and of its Markdown copy count too. Choose a column's heading to sort by it, and **Download CSV** for the same report as a spreadsheet file. Admins only.

### Changed

- **The analytics page shows at once:** the range links and a placeholder come first, and the report fills in when it's read; the refresh every 30 s reloads only the report. Reading it is quicker too: the days are read in parallel, and the finished ones are kept in memory for a few minutes, so a refresh reads only yesterday and today. The posts report reads faster the same way.
- **The reset has its own page:** Site settings' danger zone leads to Reset the site, where you tick what to delete. Content, media, settings and the search index are ticked at first; comments, reactions, contact messages, analytics, added editors, connected apps, the audit log, the spam protection counters and uploaded backups can be ticked too. You're signed out only if the reset deleted you, as an added editor.
- **Admin pages explain themselves on request:** a page's explanation, which stood under its title, is now under an (i) beside the title; it opens with a click, Enter or Space, and closes with Escape or a click elsewhere.
- **Special pages:** the home page's page, the privacy policy, the terms and the contact form's text are now pages without a slug (**No address of its own** in the editor). Site settings choose them by page and show them at `/`, `/privacy`, `/terms` and `/contact`; they aren't in the menu (search and the sitemap have them), and `privacy`, `terms` and `contact` are reserved slugs. **Upgrading:** Site settings no longer find these pages by slug: remove each one's slug in the editor and choose it again in Site settings, the home page's page too ([deploy](docs/deploy.md#privacy-policy-and-terms)). The sample site's three pages are special pages.
- **The editor's split view scrolls in step:** side by side, the text and the preview are at most as tall as the window and each scrolls on its own; scrolling either one brings the other to the same place, so the text no longer runs out halfway down a post with images. A pane with nothing more to scroll passes the wheel on to the page. Stacked, on a narrow screen, they work as before.
- **The load test is named in the analytics:** its requests count as the bot "Grafana k6" rather than an unnamed bot.
- **`visitor` is a reserved slug:** the addresses under `/visitor` serve what visitors send (ADR 0011), so a page can no longer be called `visitor`.
- **Messages:** a whole row opens the message, each row has its own Delete button, the list has a Refresh button, and a message links back with "Back to messages".
- **The menu editor shows where each item goes:** an item that goes to the blog or a page shows that address in its Address field, rather than the `/tags` example, which only empty address rows keep now.
- **Runtime async:** Weesite's own code is compiled with .NET 11's runtime async, as ASP.NET Core and the .NET libraries already are. Async calls allocate less, and stack traces in the logs no longer show the compiler's state machine frames.

### Fixed

- **Forms are sent once:** a second press of a form's button, or of Enter, while the first was still on its way sent it again, so a slow action such as the reset could run twice. A form that posts now waits for its answer, its buttons marked busy; a download opens again after a few seconds.
- **The admin menu marks Pages while you edit a page:** it marked Posts.
- **Reactions after a reset:** deleting the reactions kept the record of who had already reacted that day, so a visitor's new reaction could go uncounted and a changed one could show a negative count in the analytics. The reset now deletes that record with the reactions, and taking back a reaction that isn't counted changes nothing.
- **Admin messages have room under the buttons:** a message such as "Saved." or the reset's "Deleted: …" sat flush under the page's buttons.
- **Site settings keep a chosen page that isn't published:** the privacy, terms and contact page lists showed published pages only, so a chosen draft showed as "none" and the next save quietly removed it. A draft stays chosen and says so; a page that's no longer suitable stays listed, and the save says to choose another.
- **Site settings' two-column fields line up:** a longer help text in one column pushed the other column's field down.
- **Admin tables fit a phone:** on a narrow screen, text hidden for screen readers inside a table or the tabs could widen the whole page, so it scrolled sideways (Messages, Posts and others). It now stays inside the table's own scrolling.
- **The analytics per-day table fits its dialog:** all five columns show without scrolling sideways; the dialog was narrower than the table. It has a close button beside its title too, so a long table needn't be scrolled to close it.
- **The editor's reading time matches the site's:** the editor counted the Markdown as typed, so table pipes, list markers and heading marks counted as words, and a post with tables could show a minute more than its page. It now counts the plain text, as the site does.
- **Scheduled posts become published:** when a scheduled post's or page's time comes, it's now saved as published, with an audit entry by the schedule, rather than staying "scheduled" in storage while the site showed it. With IndexNow on, the search engines hear about it then.
- **Ctrl+S in the editor:** saves before you've clicked into a field too. Before, right after the page loaded or saved, it opened the browser's own "Save page" dialog.
- **Saving without changes:** pressing Save with nothing changed, in the post and page editor or on a settings page (site settings, menu, tags, colour theme, your profile), no longer adds a version or an audit entry; the page says nothing had changed. A post written by hand or by an app keeps its formatting until something in it changes. Over MCP, `update_item` answers `unchanged` the same way.
- **Uploaded photos kept as they are when possible:** a JPEG or WebP without metadata is stored as uploaded unless re-encoding makes it smaller. Before, every one was re-encoded at quality 85, so a photo compressed harder grew and lost a little quality. Photos with metadata (camera, location) are still re-encoded without it.
- **HEAD requests:** media files, the feeds, the sitemap, `robots.txt`, `llms.txt`, the Markdown versions of posts and the social cards answer HEAD as they answer GET. Before, they answered 404 or 405, so link checkers and crawlers that probe with HEAD reported them as missing.

## [1.0.0] - 2026-11-16

The first release: a personal site on Azure that you deploy from your own fork, with an editor, search and agent support. [Install Weesite](docs/install.md) walks through a first install.

### Added

- **The public site:** posts and pages from Markdown, tags with colours, related posts, a one-level menu and a home page you set up. Reading aids: "On this page", heading links, a top link, images that open larger, code highlighted on the server with an optional file name, footnotes and print styles. Light, dark and system themes, with your own colours. It works without JavaScript.
- **Search:** keyword and meaning search in the app itself (SQLite FTS5 and a local embedding model, merged by rank), English by default and about a hundred languages with the multilingual model. No outside search service.
- **Search engines and feeds:** canonical addresses, structured data, social cards drawn for every post, a sitemap, `robots.txt`, Atom and JSON Feed.
- **Agent support:** `llms.txt`, every page as Markdown (`Accept: text/markdown`), a read-only MCP endpoint for the public content, and an MCP endpoint for editors (`/mcp/editor`) with OAuth sign-in, three consent levels, Client ID Metadata Documents and dynamic registration.
- **The editor at `/admin`:** sign-in with Microsoft or Google; admins and authors; a Markdown editor with a toolbar, live preview and autosave; drafts, scheduling, archiving and deleting; versions with a diff and restore; media with alt text, WebP sizes and references; the menu, theme, tags, site and footer settings; editors with email invitations; an audit log with a CSV export; backups to download and import; a factory reset; and HTML export of a post for publishing elsewhere.
- **Analytics:** page views counted on the server, without cookies and without storing IP addresses, AI agents included; an editor's own visits are left out.
- **Languages:** one site language, any language; the public text in English and Hungarian; posts in another language marked as such.
- **Infrastructure:** OpenTofu for Azure Container Apps, Blob and Table Storage, Key Vault and monitoring, test and prod, with a bootstrap that sets up the state, its encryption, the identities and the GitHub environments. A second install fits in the same subscription.
- **Delivery:** GitHub Actions that lint, test (unit, integration and browser), scan and publish the image, plan and apply the infrastructure with a policy baseline (Rego, TFLint, Checkov), deploy to test, and promote the same image to prod after approval.
- **Security and accessibility:** a strict CSP with no inline code, `__Host-` session cookies with a seven-day limit, rate limits, upload and import checks, audit logs for Key Vault, storage and the state, and WCAG 2.2 AA checked with axe in the browser tests and by hand with a screen reader.
